AI Code Review Agent

◆ What it does

AI Code Review Agent is a production-deployed GitHub App that brings automated, LLM-powered code review into a normal GitHub workflow. On every pull request or push, it pulls the diff via the GitHub API, sends it to a large language model for review, and posts the findings back as line-anchored inline comments tagged by severity. It deliberately stays silent when there's nothing significant to flag, so it adds signal rather than noise.

Its distinguishing feature is a human-in-the-loop approval gate: instead of auto-posting, each review is routed to a Telegram bot with Approve / Reject buttons, and posts to GitHub only after a maintainer approves — keeping a human in control of what the bot says publicly.

◆ Key features

  • Inline PR & commit-level reviews, severity-tagged (🔴 blocker · 🟡 warning · 🔵 nit); quiet below a configurable threshold.
  • Human-in-the-loop Telegram approval — reviews are held, approved/rejected via inline buttons, with failure alerts and gate modes (gate everything, or only reviews containing a blocker).
  • GitHub App identity with self-rotating installation tokens, so comments post under a dedicated bot account.
  • Reviews only the newly pushed changes on PR updates (compare-diff), plus a /rereview command to force a fresh pass.
  • Deduplication so redelivered webhooks never double-post.

◆ Engineering highlights

  • Stateful approval over a stateless webhook — approval turns synchronous posting into deferred posting: the fully-rendered GitHub payload is persisted under a single-use token and replayed on approval. The Telegram callback is fast-acknowledged and processed in the background so a slow GitHub round-trip can't cause duplicate deliveries.
  • Security-conscious throughout — HMAC verification of GitHub webhooks, a shared-secret + chat-id check on the Telegram callback, HTML-escaping of user-controlled content, a fail-closed approval gate, and secrets kept out of the Docker image.
  • Prompt engineering — the review prompt is tuned to produce specific, senior-level findings (name the exact symbol, state the concrete failure and its trigger, give a fix) rather than generic advice, with calibrated severity levels.
  • Resilient LLM integration — diff-size budgeting with automatic shrink on oversized requests, and back-off/retry on rate limits.
  • Production ops — auto-deploys from main on Render, kept warm by a health-check monitor, with a SQLite store that survives restarts for both dedupe and pending approvals.
  • ~140 automated tests covering webhook dispatch, review generation, and the full approval flow.

◆ What I'd highlight in an interview

Turning a stateless webhook into a stateful approval flow with single-use replay tokens and background-processed callbacks.
A fail-closed security posture: HMAC + shared-secret checks, HTML-escaping, and secrets kept out of the image.
Prompt calibration for specific, senior-level findings — and knowing when to stay quiet to preserve signal.
