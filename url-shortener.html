URL Shortener Service

A production-deployed URL shortening service with a Spring Boot REST API and a responsive Angular single-page frontend.

◆ What it does

  • Accepts a long URL and returns a short code using Base62 encoding of a database auto-increment ID.
  • Redirects visitors from the short URL to the original destination.
  • Tracks hit count and last-accessed timestamp per link.
  • Supports configurable expiry (TTL in days) with automatic cleanup of expired links via a scheduled job.
  • Deduplicates URLs — submitting the same URL twice returns the existing short code; resubmitting an expired URL reactivates it instead of creating a duplicate.

◆ Technical highlights

  • Rate limiting with Bucket4j (per-IP sliding window) to protect the public endpoints.
  • In-memory cache (Caffeine) for redirect lookups, with automatic eviction on deactivation and expiry.
  • Spring Security Basic Auth protecting the admin DELETE endpoint.
  • Partial index on (is_active, expires_at) to keep the cleanup query fast as the table grows.
  • Spring profiles (local / prod) with environment-variable injection for zero-secrets-in-git deployment.
  • Angular environment swapping so the frontend points to the right API URL per environment at build time.
  • Full test suite — unit tests, @WebMvcTest slice tests with security, and rate-limit filter tests.

◆ Stack

  • Backend: Java 21, Spring Boot 3.5, Spring Data JPA, Spring Security, Hibernate, Bucket4j, Caffeine.
  • Frontend: Angular 19, TypeScript.
  • Database: PostgreSQL 16.
  • Deployed: Railway (backend + database) · Vercel (frontend).

◆ What I'd highlight in an interview

Base62 over the DB id for short, collision-free codes — no random generation or uniqueness retries.
Dedup & reactivation logic that keeps the table clean and returns stable codes for repeat URLs.
Production hardening on a "simple" service — rate limiting, caching, a partial index, and profile-based secrets.
