Agentic RAG System

A production-deployed, multi-tool retrieval-augmented generation system that decides how to answer each question — searching documents, the live web, or a GitHub repo — and grades itself before answering.

◆ What it does

An agentic chatbot that answers questions by autonomously deciding how to answer them — searching an ingested document library, searching the live web, or reading a GitHub repository — rather than always defaulting to one retrieval path. Every answer is evaluated for factual grounding before it reaches the user, and the system knows when to ask a human for help instead of guessing.

◆ Architecture

A LangGraph state machine drives the pipeline:

  1. Router

    Classifies each query — with conversation-aware follow-up resolution, so "does it cost anything?" correctly infers context from the prior turn — and plans a sequence of tool calls.

  2. Retrieval

    Hybrid search combines pgvector cosine similarity with PostgreSQL full-text search, merged via reciprocal rank fusion, so both semantic and exact-keyword queries (section numbers, product codes) retrieve reliably. A calibrated relevance threshold — tuned empirically against real embedding distances — filters weak matches before they reach the prompt.

  3. Generation

    A Groq-hosted model synthesizes the answer from retrieved context, with citations attached per source document.

  4. Judgment

    A second, larger Groq model acts as an independent judge, checking the answer against retrieved context for hallucination or contradiction. Ungrounded answers trigger an automatic query rewrite and retry — bounded to prevent infinite loops, a real failure mode I found and fixed via trace analysis.

  5. Human-in-the-loop

    After repeated failed retries, the question is persisted to a review queue. A human answers it directly in the UI, and that answer is embedded back into the vector store — so the knowledge base grows from the system's own failures.

◆ Engineering highlights

  • Full observability: every request is traced end-to-end in Langfuse — router decisions, retrieved chunks, judge reasoning, retry chains, token usage — tagged by environment. Diagnosed and fixed real production bugs (a hallucinated brand name, an infinite retry loop, a token-limit overflow) directly from trace data rather than guesswork.
  • Streaming UX: answers stream token-by-token over Server-Sent Events, with LangGraph execution running in a background thread so the Langfuse trace context survives across the generator boundary.
  • Persistent, multi-session conversations: full chat history lives in Postgres, addressable by session ID in the URL — conversations survive refreshes, restarts, and redeployments, with a sidebar to switch between them.
  • User feedback loop: thumbs up/down on every answer is recorded as a scored annotation on that answer's trace, forming the basis for quality evaluation against a golden-question regression dataset.
  • Test-gated CI/CD: a 113-test suite (all LLM calls mocked, zero API cost) gates every push via GitHub Actions; a separate workflow auto-deploys green builds to a live Hugging Face Space.
  • Zero-cost infrastructure: every dependency — inference, embeddings, database, web search, tracing, hosting — runs on a free tier with no payment method attached, deliberately designed so failure modes are rate limits, never bills.

◆ What I'd highlight in an interview

Diagnosing and fixing a production infinite-loop bug using distributed tracing rather than log-reading.
Calibrating a retrieval relevance threshold from measured cosine-distance distributions instead of guessing a constant.
Graceful degradation throughout: every external dependency has a defined fallback, so a single API hiccup never breaks the chat.
